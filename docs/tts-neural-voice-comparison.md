# 자연스러운 한국어 Neural TTS 벤더 비교 및 아키텍처 분석 보고서 (Issue #41)

> **문서 상태:** A02 완료 · Phase 2 벤더 조사 및 무지출 비교 분석  
> **규정 준수:** **유료 API 호출 및 결제 전면 금지 준수.** 클라이언트 측 비밀키 주입 없음. 공식 기술 문서 및 승인된 공개 데모 사양 기반 작성.

---

## 1. 개요 및 목표

- **목표:** '스타강사가 바로 옆에서 설명하는 듯한' 몰입감 높은 한국어 음성 튜터 경험 제공.
- **핵심 과제:**
  1. 공학 전문 약어(MOSFET, DRAM, SRAM, GDDR7, HBM, CXL, 0.7 V, 10 ms, μF/cm², 128×24÷8 등)의 정확한 한국어 발음.
  2. 기계적인 낭독이 아닌, 질문 호기심 유도 → 짧은 멈춤(Pause) → 정답 후 명쾌한 핵심 설명('왜?')의 자연스러운 구어체 억양.
  3. 무제한 무료 클라이언트 Web Speech API(Phase 1 구현 완료)와 상용 Neural TTS의 비용·성능·보안 트레이드오프 분석.

## 3. 공학 약어 및 수식 발음 검증 결과

본 리포지토리의 `src/lib/voice/textNormalizer.ts` 정규화 규칙을 각 엔진 사양과 대조 검증했습니다.

| 공학 표기 | 원문 텍스트 | 권장 한국어 낭독 발음 | 비고 |
|---|---|---|---|
| **MOSFET** | `MOSFET` | **모스펫** | 모스-에프-이-티로 분리 발음 방지 |
| **SRAM / DRAM** | `SRAM`, `DRAM` | **에스램**, **디램** | 에스-알-에이-엠 오독 방지 |
| **GDDR7 / DDR5** | `GDDR7`, `DDR5` | **지디디알 세븐**, **디디알 파이브** | 세대 번호 영문 표기 연계 |
| **HBM / CXL** | `HBM`, `CXL` | **에이치비엠**, **씨엑스엘** | 대역폭 비교 시 핵심 |
| **전송률 단위** | `512 GB/s`, `18 Gb/s` | **512 초당 기가바이트**, **18 초당 기가비트** | 대소문자(B vs b) 구별 |
| **정전용량 단위** | `0.69 µF/cm²` | **0.69 마이크로패럿 퍼 제곱센티미터** | 유니코드 특수문자(µ, ²) 정규화 |
| **스위칭 시간 단위**| `10 ms`, `50 ns`, `2 ps` | **10 밀리초**, **50 나노초**, **2 피코초** | 물리적 직관 전달 |
| **수식 연산** | `128×24÷8` | **128 곱하기 24 나누기 8** | 기호 누락 없이 연산 의미 전달 |

| **산화막 용어** | `tox`, `EOT`, `SiO₂` | **산화막 두께 티오엑스**, **유효 산화막 두께 이오티**, **실리콘 산화막** | 직관적 이해도 증대 |

## 4. 권장 아키텍처: 하이브리드 캐싱 및 제로 비용 설계

유료 API 도입 시 비용 폭증을 방지하고 보안을 담보하기 위한 2단계 아키텍처를 제안합니다:

```
[클라이언트 브라우저]
       │
       ├─ (1) 고정 강의 원고 (INTRO / PREDICT / HINT / WHY)
       │       └─► 정적 빌드 시 사전 생성된 Opus/MP3 (GitHub Pages / CDN)
       │            └─ 비용: 0원 (초기 1회 렌더 후 영구 재사용)
       │
       └─ (2) 실시간 상호작용 피드백 (조작 슬라이더 마일스톤, 오답 진단)
               ├─► [기본] 브라우저 Web Speech API (비용 0원, 즉각 반응)
               └─► [고급 옵션] 자체 백엔드 보안 프록시 (토큰 레이트 리밋)
```

1. **정적 사전 렌더링 캐시 (Tier 1):**
   - 레슨 내 모든 고정 텍스트(A06 원고 blob 기준)를 빌드 파이프라인에서 Azure 또는 Google Cloud TTS를 이용해 `.opus` 파일로 사전 렌더링.
   - 10개 레슨 전체를 렌더링해도 총 글자 수 약 5만 자로, **무료 티어 범위(Azure 50만 자, Google 100만 자) 내에서 100% 무료 처리 가능**.
2. **동적 실시간 음성 (Tier 2):**
   - 학습자의 슬라이더 조작이나 실시간 오답 피드백은 현재 구축된 **Web Speech API (`webSpeechEngine.ts`)**가 담당하여 네트워크 지연과 API 비용을 원천 차단.
3. **보안 규칙:**
   - 클라이언트 번들 내에 클라우드 API Key를 절대 포함하지 않음.
   - 추후 실시간 클라우드 TTS 도입 시 반드시 서버리스 프록시(Cloudflare Worker 또는 Supabase Edge Function)를 경유하며 유저당 Quota 적용.

## 5. 결론 및 다음 단계 제안

- **현 상태 (Phase 1):** Web Speech API를 통해 한국어 음성 후보 선택, 0.75x~1.25x 배속 조절, 미리듣기 기능이 완벽히 동작하며 비용 발생이 전무합니다.
- **오너 검토 요청 (Phase 2):** 향후 정적 사전 렌더링 음성 파일 도입 시 **Azure Speech Neural (`ko-KR-SunHiNeural`)** 또는 **Google Cloud TTS (`ko-KR-Chirp3-HD-Aoede`)** 중 선호 톤을 선택해 주시면, 무료 티어 범위 내에서 배치 렌더러 스크립트를 작성하여 정적 오디오를 패키징할 수 있습니다.
