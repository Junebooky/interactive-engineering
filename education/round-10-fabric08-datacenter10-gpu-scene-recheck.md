## Lesson08: science and numbers independently checked, teaching-contract MAJORS
**Physics/maths validated**:
- S01 RDMA uses authorized registered/mapped memory and NIC DMA; it can reduce *CPU data-plane copies* but not make CPU setup/registration/control or link bytes disappear. Host-copy two vs RDMA zero copies is a declared illustrative stack, **not universal copy count**. [NVIDIA GPUDirect RDMA programming guide](https://docs.nvidia.com/cuda/gpudirect-rdma/) confirms GPU/CPU distinct pinning and permission/topology requirements.
- S02 RoCEv2 carries RDMA over Ethernet/IP/UDP; Infiniband separate fabric transport. Congestion/discards do not vanish under RDMA, PFC/ECN configuration tradeoffs. [NVIDIA Cumulus docs](https://docs.nvidia.com/networking-ethernet-software/cumulus-linux-512/Layer-1-and-Switch-Ports/Quality-of-Service/RDMA-over-Converged-Ethernet-RoCE/) explicitly demonstrates RoCE **lossy (ECN)** and **lossless (PFC+ECN)** modes, so **do not claim PFC mandatory for all RoCE**. Queue toy with Q0=0, arrivals4−service2=+2 packets/slot, Qmax8: Q after slots1..4=2,4,6,8; next slot Q8 and drop2. With arrival2 and service2 Q remains unchanged; no "RDMA eliminates queues" claim. These are packets, not measured buffer bytes or actual PFC thresholds.
- S03 NCCL tests' busbw AllReduce factor **2(N−1)/N**, not an arbitrary physical network peak prediction. Link toy S=1 GiB and per-rank effective B=16 GiB/s: N2 `1/16=0.0625s`; N4 `1.5/16=0.09375s`; N8 `1.75/16=0.109375s`. NCCL's own [PERFORMANCE](https://github.com/NVIDIA/nccl-tests/blob/master/doc/PERFORMANCE.md) defines `busbw=algbw×factor` and ideal data-transfer lower bound under perfect overlap. Real collective algorithms and network congestion vary.
- S04 optical ideal payload 1 decimal GB over 100Gb/s => `8e9/1e11=0.08s` raw serialization lower bound, **not actual file/network completion**. 8 links×2 endpoints×4 W/module =>64 W total *toy module only*, not included switch/laser/cooling power if not explicit. Fiber transport doesn't eliminate electro-optic power, and fiber vs HBM TSV is distinct. No vendor SKU measured.

## Lesson10: math and science correct, causal/learning MAJORS
**Physics/math verified**:
- S01 Roofline `P≤min(Ppeak, I×BW)`: Ppeak4e12 FLOP/s, BW1e11 B/s, ridge40 FLOP/B, at I10⇒1 TFLOP/s, I80⇒4 TFLOP/s; BW2e11⇒ridge20 FLOP/B. Arithmetic intensity is **FLOPs per DRAM/HBM bytes actually transferred at chosen memory boundary**, including reuse; not a latency guarantee. Original [Williams, Waterman, Patterson 2009 Roofline paper](https://escholarship.org/uc/item/5tz795vq) confirms upper-bound concept.
- S02 prefill vs token-by-token decode and KV residency: increasing context or batch increases needed KV states for ordinary full attention, with implementation/eviction/quantization exceptions. Formula as written is **per sequence** approximation when batch=1 (see below).
- S03 The Green Grid [official legacy PUE definition](https://www.thegreengrid.org/resources/glossary?combine=pue): facility annual energy / IT equipment energy, 1MW constant IT and PUE1.4 vs1.2 → average facility power1.4 vs1.2MW, overhead0.4 vs0.2MW toy. **PUE alone says nothing about queries/s or accelerator utilization**.
- S04 common-switch single failure can take down two servers despite redundancy. Meaningful resilience requires topology, independent domain, health detection, failover and state/consistency/cold start, not server-count alone. No numerical SLA from provided inputs.

**R10-05 10-S04 MAJOR model lacks network routing and failure/recovery evidence**
- `learnerAction` asks learner to fail NIC/switch/PSU and select retry/failover; `modelInputs` only `servers=1|2`, `switch=1|2`, `storage=1|2`, `job=infer|train`, `failureEvent`, `repairPaths manually selected`. It has **no actual server↔switch↔storage link connectivity**, `trafficRoutedVia`, `redundancyIsIndependent`, `failoverConfigured`, `healthDetected`, `replicaHasWeightsAndSession`. Thus an arbitrary switch2 toggle may falsely mark service resilient without alternate connectivity or application state; **grade cannot prove common-switch failure nor configured recovery**.
- **A06 modelInputs proposal:** `servers A|B active`, `switchCount 1|2`, `pathA=[serverA,sw1,client]`, `pathB=[serverB,sw1|sw2,client]`, `linkUp=boolean per edge`, `switchFailed=none|sw1|sw2`, `healthCheckDetected=false|true`, `failoverConfigured=false|true`, `modelWeightsResidentOnB=false|true`, `sessionStateAvailableOnB=false|true`, `checkpointDurable=false|true`; derive `healthyReachableRoute` and `serviceState=degraded|unavailable|recoveredAfterFailover` *after* student predicts. Two servers + one shared switch failing ⇒ zero client path, no automatic success. Two switches + two servers but no alternate client link ⇒ still fail; second path connected + detected failover + required model/session state ⇒ conditional service restore (RTO not modeled). Training recovery requires coherent checkpoint and restart conditions rather than just spare NIC. Never promise SLA probabilities.
- **Negative acceptance**: (i) 2 servers→same sw1 then sw1 FAIL ⇒ no service; (ii) 2 switches but both server links only sw1 ⇒ no service; (iii) actual redundant sw2 path but no failover config ⇒ no automatic recovery; (iv) sw2 path + configured failover but missing model/session state ⇒ delayed/partial restart, not instantaneous flawless; (v) all preconditions ⇒ conditional recovery. Evidence order matters: prediction→fail→detect→route→(state restore)→service update, not visited tags.
- **Before Voice:** “GPU가 멀쩡해도 답이 안 나오면, 먼저 어느 연결을 통과하는지 직접 추적해봐요.” **After** “서버 두 대가 스위치 하나를 공유하면 그 스위치가 공통 고장점이에요. 실제 우회선과 서비스 복구 설정이 있어야 다른 경로로 갈 수 있어요.”

**R10-06 10-S02 MEDIUM/MINOR physical explanation KV formula**:
- `explanation` literal `layers×heads×head_dim×tokens×bytes×2` omits batch dimension, even though `batch 1|4` is an actual student knob; also `heads` should be number of **KV heads** in GQA/MQA not query heads. The Step's `modelInputs` correctly says `KV entries proportional to context×batch`, so current numeric **state** is not contradicted, but prose formula can incorrectly mislead a student doing arithmetic.
- **A06 corrected generalized toy formula**: `KV bytes ≈ batch × seqLen × numLayers × numKVHeads × (keyDim+valueDim) × bytesPerElement`; if equal key/value dims, `2×B×L×T×Hkv×dhead×bpe`. Example choose **toy** B1/4, L2, T4/16, Hkv2, d8, bytes2: B1 T4⇒`1×4×2×2×(8+8)×2=512B`; B4 T16⇒`4×16×2×2×16×2=4096B` (8×). **Actual cache** paged, grouped-query, quantization, beam/attention mask, padding/reuse/sharding modifies allocation. Check [TensorRT-LLM official open-source KV cache documentation](https://github.com/NVIDIA/TensorRT-LLM/blob/main/docs/source/features/kvcache.md) and [vLLM official KV-cache type code](https://github.com/vllm-project/vllm/blob/main/vllm/v1/kv_cache_interface.py). Do not confuse total active batch KV capacity with a single request's per-token KV.
