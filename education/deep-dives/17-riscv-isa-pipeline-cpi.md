## [17-R1] ISA contract vs microarchitecture; architectural state
Official [R1] RV32I unprivileged programmer-visible `x0..x31`, each XLEN32 bits, `x0` hardwired zero, separate `pc` current instruction address; RV32I uses load/store memory architecture, ALU arithmetic operates on registers, memory byte addressed. Plain 32-bit RV32I without compressed extension has 4-byte instruction words in toy; an RVC extension could have 2-byte compressed instructions, so do NOT claim pc always+4 on every real RISC-V. Branch/jump also modify PC. Educational subcase x2=0x100, M32[0x100]=9, `addi x1,x0,5`→5, `sw x1,0(x2)`→M=5, `lw x3,0(x2)`→5, `add x4,x3,x1`→10. Writes `addi x0,x1,7` do not change zero, but execution may still have effects unrelated to x0 writes. No MMIO, exceptions or alignment traps in toy. Endianness irrelevant to 32-bit word read/write same value in this toy.

## [17-R2] Five-stage classic simple pipeline (teaching abstraction)
Assume single issue, 5 stages IF / ID / EX / MEM / WB, each stage exactly one toy cycle, no initial/cycle overlap hazards, four fully independent register-ALU instructions with no branch or cache stalls. Instructions enter IF in cycles1,2,3,4, first WB in cycle5, fourth WB in cycle8. **Total time for completing four = 5+(4-1)=8 cycles**, first instruction latency5 cycles, saturated throughput one completed instruction/cycle (after filling). A hypothetical strictly nonoverlapped design requiring all five one-cycle stages sequentially per instruction ⇒4×5=20cycles, short workload ideal speedup20/8=2.5x, not 5x on four instructions. Not a performance forecast: real clocks, balanced stages, mispredicts, memory stalls, SIMD width, multiple issue differ. gem5 SimpleCPU/Minor/O3 *do not* all use our exact five-stage toy. Sources [R2,R3,R4].

## [17-R3] RAW load-use and forwarding limitations
Toy implementation has ALU result forwarded from EX/MEM→next EX as soon as available; dependent arithmetic back-to-back may need zero stall under toy rules. A load completes memory data at end of its MEM stage (IF1 ID2 EX3 MEM4 WB5), the immediately following consumer would ordinarily EX4 and cannot receive data ready only after end MEM4. One bubble makes consumer EX5, **one load-use stall even with forwarding**. Without forwarding, and toy register file writes in WB cycle5 first half / ID reads second half, consumer read in ID cycle5 and EX6: **two bubbles** vs ideal EX4. Thus four issued instructions baseline8 cycles; one adjacent load-use →9 with forwarding or10 without in this precisely defined toy (assuming no later hazards/structural stalls). `bypass` paths/real memory timing depend on core design; do not teach a universally fixed one-cycle penalty or 'all dependencies fixed by forwarding'.

## [17-R4] Branch prediction and wrong-path flush
In same teaching pipeline branch resolved end of EX cycle3, branch `beq x1,x2,TARGET` with x1=x2 means actual taken; predictor not-taken causes the IF of two younger fall-through instructions in cycles2 and3 to be **speculative wrong-path work** and must be flushed before architectural commit. Toy **2-cycle recovery cost per misprediction**, counted *independently from base work*; baseline20cycle synthetic instruction work +m mispredictions ×2 gives24 for m2, 28 for m4. No branch delay slots or speculative wrong-path state commits in this toy. Real branch resolution/penalty are microarchitecture-specific; some prediction schemes/OOO deep pipelines change costs. `RISC-V ISA` does **not** mandate any branch predictor or fetch stage, gem5 O3 has branch predict/rename/commit components [R1,R3].

## [17-R5] Memory stalls, cache locality, CPI and OOOs
Define **toy 100 retired scalar instructions**, ideal single-issue baseline100cycles, load fraction0.30⇒30 loads, *per-load conditional* miss fraction0.10⇒3 misses, **incremental miss penalty**20 cycles each, no overlap, no other miss/branch hazards: total cycles100+30×0.10×20=160, CPI=1.6. If miss rate 0.05 as expected/average not integer actual trace, mean CPI=1+0.3×.05×20=1.3, 130 *expected* cycles for 100 instructions (fractional expected miss count1.5, don't imply 1.5 physical misses in one run). At toy 2GHz clock period0.5ns, 100instr×1.6CPI×0.5ns/cycle=80ns; changing clock alone doesn't guarantee same miss penalty cycles. Cache hit time may already be included in baseline, so do **not** add miss penalty to all loads again. All memory-stall misses happen on same critical path and are fully serialized in toy, unlike O3 Out-of-Order that may overlap independent loads subject to MSHR and dependency/ROB constraints; OOO can't make true RAW load-use data magically available nor claim exact numerical speedup without resource model. Source [R2,R3,R4].
