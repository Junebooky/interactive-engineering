## 20-S01 RTL function, logic synthesis, physical constraints, GDS are NOT identical
Official OpenROAD Flow [R1][R2] integrates Yosys synthesis, OpenROAD floorplan/PDN/placement/CTS/routing, KLayout GDS merge and DRC/LVS with public PDKs. RTL describes behavior, synthesis maps cells into a technology-library netlist, then floorplan/place/CTS/route produce physical wires. Passing RTL simulation proves only cases tested, not physical setup/hold, connectivity, power or all functional inputs. GDS shapes are not automatically equivalent to intended schematic. One gate-level path can have different routed wire delay depending on PDK and parasitic SPEF [R3].
**Toy physical view**: region capacity 100 arbitrary tile units, 60 occupied tiles => utilization60%; alternate capacity70 with same 60=>85.714%; **both below100%** and may differ congestion potential but no deterministic DRC or timing failure from utilization alone. If capacity50 <occupied60 => 120% toy overflow, NOT legal placement in this toy. Student must not infer node/gate length from tile geometry. Stage cards `RTL -> synthesis -> floorplan -> placement -> clock tree -> routing -> DRC/LVS` with `toolState` and separate `actualSiPass=NOT_PROVEN`.

## 20-S02 Timing is min AND max across legal clock scenarios, not frequency alone
OpenSTA consumes netlist, Liberty cell delay, SDC clocks/constraints, SPEF wire parasitic extraction and can report setup/hold separately [R3,R4]. STA is path timing **under supplied conditions and constraints**, not simulation of arbitrary input sequences. Toy single rising-edge source/target, zero clock skew, zero other external delay, all values ns, positive setup slack formula `required(T-setup-uncertainty)-arrival(CQmax+combMax+wireMax)`.
**Setup toy**: `T=1.00ns`, `tCQmax=.12`, `combMax=.55`, `wireMax=.28`, `setup=.10`, `uncertainty=.05`; arrival=.12+.55+.28=.95ns, required=1−.10−.05=.85ns, slack=-.10ns => FAIL. Improve only max wire from .28 to .18=>arrival=.85, slack0 => **nonnegative toy setup pass**, not foundry tapeout or other-corner PASS. Under all else equal, faster period T=.90 would change required=.75, fails even after wire reduction. Do NOT put setup and hold on same false path without verification.
**Hold toy independent min-delay check**: `tCQmin=.08, combMin=.06, wireMin=.04` => earliest data arrival=.18ns. `holdRequirement=.20+uncertainty=.03`=>.23ns, hold slack=arrival−requirement=−.05ns **HOLD_FAIL** (data may change too early). Add toy min-path buffer .08ns⇒min arrival=.26 and hold slack+.03ns (toy HOLD_PASS), but may also add MAX path delay and cause setup regression. Setup fix reducing delay can worsen hold, hold fix adding delay can worsen setup. Source library and realistic skew/corner variations omitted. Clock tree synthesis and on-chip variation must be separately reanalyzed; one successful scenario ≠ all corners pass [R3,R4].

## 20-S03 DRC versus LVS two independent questions
KLayout [R5,R6] documents DRC checking geometric/manufacturing design rules and LVS extracting connectivity/devices from layout and comparing to a schematic/reference netlist. Toy min metal spacing `.12µm`: layout spacing `.10µm` -> `DRC_FAIL` by `.02µm`; spacing `.13µm` passes **this ONE toy spacing rule** only, not full foundry DRC. Toy schematic requires 2 devices and one connecting via, layout extracted netlist missing that via => `LVS_FAIL` even though spacing .13 passes. Add via ⇒ toy topology connectivity matches and partial LVS pass, without proving full LVS or electric timing. A `DRC_PASS` check is not equivalent to functional equivalence/LVS, and passing both is not fabrication signoff or functional behavior proof. KLayout vendor public docs support exact device/netlist extraction semantics [R5,R6].

## 20-S04 Design-for-Test fault models and test coverage, not random silicon yield guarantee
Siemens Tessent official engineering [R7][R8] distinguishes scan, ATPG fault models (stuck-at and at-speed transition, bridges/cell-aware), compression and manufacturing test. Defect test coverage **depends on selected fault list and detectable definition**; percentage detection of modeled faults does not equal defective-unit reject rate, shipped quality, or 100% confidence in all physical defects.
Toy fault list100 modeled eligible stuck-at targets, `detected90|95`; modeled coverage90/100=90%,95/100=95%. Additionally `untestable=0|5` must be counted separately and denominator policy stated: when faults categorized untestable, do not silently divide by95 and proclaim production yield. For example set **100 total candidate faults, detected90, classifiedUnreachable5, remaining5 undetected**: broad modeled coverage=90/100=90%; testable-only coverage=90/(100−5)=94.7368% (a different explicitly labeled denominator). A reader manipulating `untestable` must know exactly which pool is excluded and ensure detected+unreachable<=total. `manufacturingDefectEscapeProbability=NOT_PROVEN` no production test calibration.

## 20-S05 Power-domain OFF isolation, retention and power intent are independent
IEEE **1801-2024 UPF** power-intent modeling [R9] covers power domains/states/isolation/level shifters/retention concepts without itself proving behavior on hardware. For a simple toy domain A (switchable logic), always-on domain B receives an output, A power OFF means A's combinational output is **UNKNOWN**, unless isolation enforces a safe clamp for B. State retention requires successful save **before OFF** and restore **after ON** for chosen retained registers. An isolation clamp is not data retention; save/restore doesn't prevent off-domain X outputs without appropriate isolation. Different voltages may need level shifters; all such cells must be correctly placed and verified. Source UPF constraints alone are not power-state silicon functional pass.
Toy booleans `powerAOn`, `isolationEnabled`, `saveBeforeOff`, `restoreAfterOn`, `retentionCellAvailable`. If A OFF & iso false ⇒`UNSAFE_UNKNOWN_OUTPUT`. If A OFF & iso true ⇒`CLAMPED_OUTPUT` for B only, retained data `NOT_PROVEN` unless availability+save; when A ON after OFF, restored prior register state only if retentionCellAvailable AND saveBeforeOff AND restoreAfterOn; else `STATE_NOT_RESTORED`. `powerStateCorrect=TOY_CONTRACT_VALID` only after both isolation on OFF and retention when asked; no actual UPF or gate-level sim run.
