## 1. SRAM 05: TWO NEW BLOCKERs in standalone A05 UI state transitions
### R3-SRAM-01 · BLOCKER · 05-S01: lost SRAM bit magically returns after power cycle
**Why factually incorrect:** 6T SRAM retains logical state *while the power remains on*, but does **not guarantee recovery of its previous value after VDD power-off**, despite some real cells preferentially powering up in a certain state. [MIT OCW 6.004 SRAM lecture, transcript 1:40–2:39](https://ocw.mit.edu/courses/6-004-computation-structures-spring-2017/resources/sram-6-58-/) explicitly describes power-dependent bistability.
**Exact source path:** `fresh()` stores `q:0, supply:true`; `setSupply(false)` in A05 Lab only changes `supply` but preserves `state.q`; `latch(q,feedback,supply)` returns `null` only *while supply is false*; `setSupply(true)` immediately renders the same old Q, as if it recovered the original bit. A05 unit tests assert power-off displays null but **do not assert power OFF→ON must not recall old Q**.
**Learner reproducible actions:** open 05-S01 → make prediction → Q=1 → VDD OFF (visual Q '?') → VDD ON without reprogramming → visual deterministic Q=1: physically misleading recovered bit.
**Suggested fix A05:** change state to `q:Bit|null` or `initialized:boolean`; when supply turns off **invalidate valid storage**. On reapply VDD show `미확정 · 초기화/쓰기를 해 보세요` until learner explicitly initializes an example bit, not spontaneously reuse old value. `latch` logic must not show `stable:true` for unknown Q after power returns. Do not claim a stochastic random value if no probability model. **A06** updates canonical story to emphasize “전원 OFF 후 이전 bit 자동 복구 보장 X”.
**Regression user flow:** choose Q1 → off → on → Q not known/recovered, Q1 selected explicitly again → Q1/Qbar0 valid. Check DOM/readout and voice for correct unknown state.

### R3-SRAM-02 · BLOCKER · 05-S02: while WL is ON, changing BL is shown as a write, but written bit vanishes when WL is turned OFF
**Why factually incorrect:** When wordline connects the access transistors and the write driver is active, BL/BLB drive can overwrite the cross-coupled latch and the resulting Q persists after WL falls, while power remains. [MIT OCW 6.004 SRAM lecture](https://ocw.mit.edu/courses/6-004-computation-structures-spring-2017/resources/sram-6-58-/).
**Exact source path:** `setWl(value)` updates `state.q = access6T(state.q,value,state.bl,state.mode).q` but `setBl(value)` *only* updates `state.bl`, never `state.q`. Meanwhile `SramSceneVisual` recomputes `const cell=access6T(state.q,state.wl,state.bl,state.mode)` **for display only**. Thus with WL ON/write, changing BL temporarily displays new Q, but the persisted `state.q` remains old. WL OFF updates Q from the stale persisted value, making the cell jump back. `setMode('read')` with WL ON can immediately expose stale Q too.
**Learner reproducible:** 05-S02 → predict → initial Q0/BL0/WL OFF/WRITE → WL ON → BL1/BLB0 → display Q1 → WL OFF → display Q0 (**wrong lost write**). Also switching READ after setting BL1 while WL ON can show wrong Q0.
**Fix contract A05:** one canonical state transition `apply6TWrite` on **any event changing BL, WL, or WRITE mode** when `wl===1 && mode==='write' && supplyActive`. Store Q once in canonical state; `SramSceneVisual` should display persisted canonical Q rather than independently recomputing a phantom write result. Use a temporal toy state (not physics time-resolved): when WL0, changing BL must preserve Q; when WL1/write, driver overwrite persists; when WL1/read, sensed bit reflects Q and `readDisturbPossible` is shown but the read toy does not overwrite Q. If user toggles WRITE→READ while WL1, ensure Q remains last written value.
**Regression both orderings** BL1→WL ON→WL OFF **and** WL ON→BL1→WL OFF must store Q1, plus BL only/WL OFF must not write, plus WRITE→READ path. A05 prior 7-case Chromium PASS tests **only first ordering**: it is not evidence for the second. A02 must not integrate the broken standalone state machine.

**Round 03 gate:** these two affect **only 05 SRAM scene's scientific claim**; `BLOCKER_OPEN` until A05 supplies corrected scene SHA and stateful Chromium/user-flow tests (A07 independent source retest).
